# Day 40 — Capstone Part 2 — Flight Club

## Core Concepts
- **Customer acquisition via Google Form** — form responses land in a sheet; Sheety exposes it read-only (`GET`). The application never writes to the customer list.
- **Two-endpoint data layer** — one `DataManager`, two Sheety endpoints (prices: GET+PUT; users: GET), each validated against only the variables it uses.
- **Non-stop → indirect fallback** — first search pins `stops=1` (nonstop only); if the cheapest is the "N/A" sentinel, retry with the param omitted; if still empty, skip the route.
- **Stop count from segments** — `len(itinerary["flights"]) - 1`; no API field required.
- **Fan-out notifications** — on a confirmed deal (sheet updated first), loop customers and send personalized SMTP mail.

## Syntax / Key Commands
```python
params["stops"] = "1"          # nonstop only; omit the key to allow any stops
```

## Pitfalls
| Mistake | Why It Happens | Fix |
|---------|----------------|-----|
| Customer sheet given write methods | Assuming the app manages signups | The form writes; the app only GETs — restrict Sheety methods accordingly |
| Assuming indirect flights exist in test data | Course docs promise the fallback | Course API routes never exceed 1 stop; the ladder stays implemented, expectation documented |
| Duplicate search code for the fallback | Copying the non-stop call | One `nonstop_only` flag toggles the param |
| Email before sheet update confirmed | Eager notification ordering | Update sheet → on success → fan-out |
