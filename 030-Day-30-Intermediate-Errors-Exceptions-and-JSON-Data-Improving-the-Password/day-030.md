# 📗 Day 30 — Errors, Exceptions and JSON Data Improving the Password

## Core Concepts

- **Exceptions** — Unexpected events (runtime errors) that crash the program. Handled using `try/except` blocks to prevent crashes.
- **Exception Handling Structure:**
  - `try`: Tests a block of code for errors.
  - `except`: Handles the specific error (e.g., `FileNotFoundError`).
  - `else`: Executes if NO exception occurred.
  - `finally`: ALWAYS executes, regardless of whether an error occurred.
- **Raising Exceptions** — Manually triggering an error using the `raise` keyword (e.g., `raise TypeError("Only integers")`).
- **JSON Module** — Allows serializing Python dictionaries to JSON formatted text files (`json.dump()`) and deserializing them back (`json.load()`).

## Syntax / Key Commands

### Try/Except/Else/Finally
```python
try:
    file = open("data.json", "r")
except FileNotFoundError:
    print("File not found.")
else:
    print("File opened successfully.")
finally:
    print("Execution complete.")
```

### Raising Errors
```python
x = "hello"
if not type(x) is int:
    raise TypeError("Only integers are allowed")
```

### JSON Read/Write Pattern
```python
import json

# Write
with open("data.json", "w") as f:
    json.dump(my_dict, f, indent=4)

# Read
try:
    with open("data.json", "r") as f:
        data = json.load(f)
except FileNotFoundError:
    data = {}
```

## Watch Out / Pitfalls

| Mistake | Why It Happens | Fix |
| --- | --- | --- |
| Bare `except:` clause | Catches ALL errors (including keyboard interrupts) | Always specify the error type: `except FileNotFoundError:` |
| `json.decoder.JSONDecodeError` | Trying to `json.load()` an empty file or invalid JSON | Ensure the file was written using `json.dump()` and isn't empty |
| Forgetting `indent=4` | JSON file writes as one massive, unreadable line | Pass `indent=4` to `json.dump()` for pretty-printing |
