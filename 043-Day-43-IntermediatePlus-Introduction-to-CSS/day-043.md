# Day 43 — Introduction to CSS

## Core Concepts
- **The cascade** — competing rules resolve by specificity: tag < class < ID < inline (`!important` overrides all; avoid).
- **Three application methods** — inline, `<style>`, `<link>`; linked stylesheets are the default choice.
- **Selector families** — basic (tag/class/ID/universal), combinators (descendant, child `>`, adjacent `+`, general sibling `~`, group `,`), attribute (`^` `$` `*` `~` `|`), state pseudo-classes, position pseudo-classes, pseudo-elements.
- **Modern selectors** — `:is()` (any match), `:where()` (zero specificity), `:has()` (relational/parent), `:focus-visible`, `:focus-within`.
- **Custom properties** — `:root` tokens and per-element values (`style="--c: #f00"`) drive themeable components.

## Syntax / Key Commands
```css
:root { --ink: #1e1e2e; }
.card { --c: #000; }
.card .swatch { background: var(--c); }
.card:focus-visible { outline: 3px solid var(--accent); outline-offset: 3px; }
.fw:focus-within { background: var(--peach); }
.box:has(.star) { background: var(--yellow); }
```

## Pitfalls
| Mistake | Why It Happens | Fix |
|---------|----------------|-----|
| Reaching for `!important` to win specificity fights | Specificity feels unpredictable mid-edit | Fix the selector instead; `!important` begets `!important` |
| Styling children from the parent's rule | Inherited vs targeted confusion | Target the child directly; inheritance only covers text properties |
| Inline styles during debugging | Fast, then forgotten | Move to the linked stylesheet before committing |
| `/* */` comments in JS files | CSS habit carrying over | Valid but unconventional; use `//` in JavaScript |
