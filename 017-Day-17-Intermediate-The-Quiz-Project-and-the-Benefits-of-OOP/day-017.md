## Syntax / Key Commands

### Class Definition & Object Interaction

```python
class User:
    def __init__(self, name):
        self.name = name
        self.id = uuid.uuid4()  # Unique ID generation
        self.follower = 0
        self.following = 0

    def follow(self, user):
        user.follower += 1   # Modifying the OTHER object's attribute
        self.following += 1  # Modifying THIS object's attribute

user_1 = User('Sarah')
user_2 = User('Mona')
user_1.follow(user_2)  # Sarah follows Mona
```

## 🛠️ Projects

### Mini-Quiz-Game 🧠 (Main Project)
> 📂 [**View source →**](Mini-Quiz-Game/main.py)

A terminal True/False quiz game that pulls questions from the [Open Trivia Database](https://opentdb.com/). 

**Architecture:**
- `question_model.py`: Defines the `Question` class (holds text and answer).
- `data.py`: Contains the raw question data (list of dicts).
- `quiz_brain.py`: Defines the `QuizBrain` class. Tracks `question_number` and `score`. Contains `has_question()`, `ask_question()`, and `check_answer()` methods.
- `main.py`: Parses `data.py` into `Question` objects, feeds them to `QuizBrain`, and runs the game loop.

## ⚠️ Watch Out / Pitfalls

| Mistake | Why It Happens | Fix |
| --- | --- | --- |
| Forgetting `self` in method params | Defining a method without the instance reference | Always use `def method_name(self, ...):` |
| Not updating object state | Calling `follow()` but only incrementing `following` | Remember to update *both* objects involved in the interaction |
| Procedural code in OOP | Writing the quiz loop in `main.py` instead of the class | Move logic into class methods (e.g., `quiz.ask_question()`) |
