# 📗 Day 35 — API Keys, Authentication & Environment Variables - Rain Alert

## Core Concepts

- **API keys** — the license that authenticates and meters your usage on premium APIs. Handle like passwords.
- **Environment variables / `.env`** — secrets live in `.env`, loaded via `python-dotenv`, excluded from git via `.gitignore`.
- **API chaining** — Geocoding API (city → lat/lon) feeds the Forecast API (coords → weather).
- **Condition codes** — `weather[0].id < 700` ⇒ thunderstorm/drizzle/rain/snow ⇒ umbrella.
- **Substitution pattern** — Twilio (SMS) is unreachable from Iran (sanctions); transport swapped to SMTP, core API skills untouched.

## Watch Out / Pitfalls

| Mistake                                                | Why It Happens                                        | Fix                                                                      |
| ------------------------------------------------------ | ----------------------------------------------------- | ------------------------------------------------------------------------ |
| `requests.exceptions.MissingSchema`                    | Bare host `api.openweathermap.org/...` with no scheme | Always `https://` — requests never guesses                               |
| Secrets as module-level constants                      | Course demos hardcode for speed                       | `.env` + `os.getenv()` from day one; `export` only for one-off shell use |
| `check_for_rain()` reading module-level `weather_data` | Quick-script habit                                    | Pass the data in: `check_for_rain(data)` — keeps the function testable   |
